# Ask-or-Act: Final Evaluation Plan

This plan is fixed **before** the final evaluation runs. Results are reported for
everything listed here, whether or not they support our expectations. Any change
made after the final runs start is recorded in the deviations log at the end,
with its reason.

## 1. Frozen version

- Code: git tag `v1-final-eval` in `~/ask_or_act` (and the HuNavSim commits in `~/hunav_ws`).
- Software: Ubuntu 22.04 (VirtualBox), ROS 2 Humble, Gazebo 11.10.2, Python 3.10,
  numpy 1.21.5, pandas 1.3.5, scikit-learn 0.23.2, scipy 1.8.0.

## 2. Fixed settings

| Setting | Value |
|---|---|
| Robot | TurtleBot3 Burger, straight line (2.9, 0.1) to (-2.9, 0.0), 0.18 m/s |
| Pedestrian radius / collision distance | 0.3 m / 0.4 m (centre to centre) |
| Tracking | 10 Hz, Gaussian position noise per condition (nominal 0.03 m, noisy 0.10 m) |
| Engagement distance / decision deadline | 1.0 m / 0.6 m ahead of the robot |
| Ask band | ask if 0.2 < p < 0.8 (yield if p >= 0.8, go if p <= 0.2) |
| Probability smoothing | mean of last 5 predictions |
| Answer timeout / yield timeout | 5 s / 8 s, then cautious rule (stop only within 1.5 m of the line) |
| Response model (baseline) | always answers, after 1.5 s, truthfully |
| Predictor | MLP (32, 32), trained on nominal data only |
| Decision window (for isotonic_dw) | last 3.5 s before a crossing pedestrian reaches the line |

## 3. Conditions, methods, scenarios

- **Conditions:** nominal, noisy (primary); slow, fast, long_pause, combined (secondary).
- **Methods:** always_act, always_cautious, always_ask, oracle, threshold:raw,
  threshold:isotonic@stale, threshold:isotonic@recal, threshold:isotonic_dw@recal.
- **Scenario families:** clear_cross, clear_noncross, hesitant (x2 intents),
  late_turn (x2 intents), slow_cross, wait_far.
- **Seeds:** seeds used during development (0-99, 1000-3999 per condition block,
  5000-5099) are **not** used for final results. Final evaluation uses
  **seeds 7000-7099** in each condition block (10000 x condition index + 7000..7099):
  100 seeds x 8 families = 800 episodes per method and condition,
  of which 400 are crossing encounters.

## 4. Metrics

- **Primary:** collision rate on crossing encounters; questions per episode.
- **Secondary:** mean delay versus free driving (s); stopped time with
  not-crossing pedestrians (s); ask rate in clear vs ambiguous scenarios;
  timeout rate (expected 0).
- **Predictor:** ECE (15 bins), Brier score, AUC, on all test samples and on
  decision-window samples, per condition.

## 5. Hypotheses and tests

All method comparisons are **paired** (same scenarios for every method).

| | Hypothesis | Test |
|---|---|---|
| H1 | Under the noisy shift, raw and stale-calibrated confidence give more collisions on crossing encounters than decision-aware recalibrated confidence. | McNemar exact test (paired collisions) |
| H2 | Under the noisy shift, decision-aware recalibration gives fewer collisions than ordinary (all-sample) recalibration. | McNemar exact test |
| H3 | Under nominal conditions, threshold:isotonic_dw@recal asks fewer questions than always_ask, with a collision rate no more than 2 percentage points higher (non-inferiority). | Wilcoxon signed-rank (questions); one-sided 95% CI on the paired collision difference |
| H4 | Decision-window ECE is lower for isotonic_dw than for all-sample isotonic calibration, under every shifted condition. | Descriptive, bootstrap 95% CIs over scenarios |

Holm-Bonferroni correction across H1-H3 (family-wise alpha = 0.05).
Response-reliability results are **exploratory** and reported descriptively
with 95% Wilson intervals; the development sweep already showed no advantage
for confidence-based asking, and this will be reported as found.

## 6. Robustness checks (reported in full)

1. **Ask-band sweep:** bands 0.1-0.9, 0.15-0.85, 0.2-0.8, 0.3-0.7, 0.4-0.6;
   plot collisions vs questions per calibration method (nominal and noisy).
2. **Predictor seeds:** MLP retrained with random_state 0-4, plus logistic
   regression; repeat H1-H3 comparisons.
3. **Full response grid:** all 18 combinations of response probability
   (1.0, 0.8, 0.5), delay (0.5, 1.5, 3.0 s), accuracy (1.0, 0.9).
4. **Deadline sensitivity:** decision deadline 0.5 and 0.7 m.

## 7. Gazebo validation

- 40 final-seed scenarios (5 per family), nominal and noisy, for always_act,
  always_ask, threshold:raw, threshold:isotonic_dw@recal (320 Gazebo episodes).
- Compare with the offline simulator on the same scenario IDs:
  collision outcome agreement (%), correlation of minimum distance,
  equality of question counts.
- Agreement criterion stated in advance: >= 90% of episodes with the same
  collision outcome. If not met, the offline results are reported as
  indicative only and the discrepancy is analysed.

## 8. Reporting rules

- All tables and figures are generated by scripts from the frozen runs;
  no hand-edited numbers.
- Every method, condition and hypothesis above is reported, including results
  that do not support our expectations.
